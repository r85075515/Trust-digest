10:T7cd,A decade-old vulnerability nicknamed *sshole lets attackers log into some Linux devices over SSH without any password, Ars Technica reports, turning a routine login mechanism into an open door on affected systems.
What happened
The flaw sits in the interaction between OpenSSH, the code library that implements SSH connections, and musl, the lightweight alternative to the standard C library (libc) that Alpine Linux uses in place of the glibc found in most other distributions. On affected configurations, that interaction lets an attacker authenticate over SSH with no password at all. Ars Technica describes the vulnerability as a decade old, and says devices running some configurations of Alpine Linux are affected, with other distributions possibly exposed as well. The feed summary does not name a CVE identifier, a patch, or a list of affected versions, so the precise scope is not spelled out here.
Why it matters
Passwordless SSH access is about as serious as a login flaw gets: anyone who can reach an exposed device on the network could walk in without credentials. Alpine Linux is widely used in containers and small-footprint systems, so a flaw in its default stack can reach far beyond desktop machines into servers and embedded devices. Until the scope is pinned down, administrators cannot tell from this report alone whether their own systems are affected, which is why the disclosure matters even before full technical details circulate.
